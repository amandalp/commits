# Commits

> **I'm going to [do something] by [deadline].**
> Commit publicly → get cheered on → ship it → celebrate → commit again.

Commits is a mobile-first social network built around public commitments — Threads × Pie,
where the defining content object is a commitment and the defining loop is:

**I said I would → people saw → people cared → I did it → we celebrated.**

This is **one deployable full-stack Next.js app** (App Router) backed by **Supabase**
(Postgres + Auth + Storage). No monorepo, no separate API server — all server logic lives
in Server Actions and Route Handlers, and the repo root deploys directly to Vercel.

## Quick start

### 1. Create a Supabase project
[database.new](https://database.new) → grab your keys from **Project Settings → API**.

### 2. Run the schema
Open the Supabase **SQL Editor**, paste the contents of [`supabase/schema.sql`](supabase/schema.sql),
and run it. This creates every table, enum, index, RLS policy, the notification-fan-out
triggers, the new-user bootstrap trigger, and the public `media` storage bucket. It's safe
to re-run.

### 3. Configure environment
```bash
cp .env.example .env.local
```
Fill in:
```
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-public-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key   # server-only, for the seed script
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

### 4. Auth settings (Supabase → Authentication)
- **URL Configuration → Redirect URLs:** add `http://localhost:3000/auth/callback`
  (and your Vercel URL's `/auth/callback` for production).
- **For fast local testing:** Providers → Email → turn **"Confirm email" off** so
  email/password signup logs you straight in. (Leave it on in production.)
- **Google (optional):** enable the Google provider and add the same callback URL.
  The button shows a friendly message if it isn't configured.

### 5. Seed a living community (optional but recommended)
```bash
npm install
npm run seed
```
Creates Amanda + 8 more people with active/shipped/overdue commits, cheers, watches, joins,
comments, updates, and notifications.

**Demo login:** `amanda@flossy.com` / `commitments` (all seeded accounts share that password).
Logging in as Amanda drops you into a populated account with an overdue commit ready to resolve.

### 6. Run
```bash
npm run dev
```
→ http://localhost:3000

## Deploy to Vercel

1. Push this repo to GitHub and **Import** it into Vercel (framework auto-detects as Next.js).
2. Add the four environment variables from `.env.local` to the Vercel project
   (set `NEXT_PUBLIC_SITE_URL` to your production URL).
3. Add `https://your-app.vercel.app/auth/callback` to Supabase redirect URLs.
4. Deploy. That's it — one project, no extra server.

## Architecture

```
app/
  (app)/                 authenticated shell (bottom nav on mobile, side nav on desktop)
    page.tsx             Home feed — For You / Following + unresolved nudge
    commit/new           Create a commit ("What are you committing to?")
    commit/[id]          Detail: commitment, context, updates, comments, join, owner panel
    commit/[id]/resolve  "How did it go?"
    commit/[id]/ship     Ship flow (confetti + proof) → SHIPPED
    commit/[id]/not-yet  Not yet → new deadline (history kept) or close
    activity             Grouped in-app notifications
    profile, u/[username], me   Profiles + My Commits (Open / Done)
  login, onboarding      Auth + 15-second profile setup
  auth/callback          Magic-link / OAuth code exchange
  share/[id]             Public, crawlable share landing + dynamic OG image
lib/
  supabase/              browser + server + middleware clients
  data/                  read queries (feed, commit, profile, comments, activity)
  actions/               Server Actions (create, cheer, watch, join, follow, comment,
                         update, ship, not-yet, profile, notifications, auth)
components/              design-system + feature components
supabase/schema.sql      full database schema, RLS, triggers, storage
scripts/seed.mjs         idempotent community seed
```

**Notifications** are generated by `SECURITY DEFINER` Postgres triggers on insert
(cheer, watch, follow, comment, join, update, ship, not-yet) — consistent by construction
and requiring no permissive insert policy. Deadline reminders come from
`generate_deadline_notifications()`; schedule it with Supabase **pg_cron** for automatic
"due soon" pings (email/push can layer on later):
```sql
select cron.schedule('deadline-pings', '*/30 * * * *',
  $$ select generate_deadline_notifications() $$);
```

**Deadlines** are stored as `timestamptz` (UTC) and rendered in the viewer's local time.
An active commit past its deadline is treated as *unresolved* and surfaced prominently
(home nudge, owner panel, My Commits) — nothing silently disappears.

**Optimistic UI** is used for Cheer, Watch, Follow, and comment likes; Commit, Ship, and
Join have tasteful micro-interactions (a cheer pop, a confetti ship).

**Appearance themes.** Two visual styles, switchable in **Settings → Appearance**:
- **Handwritten** (default) — warm paper, a marker-script wordmark and commitments with
  hand-drawn underlines, taped "shipped" notes with a circled stamp.
- **Clean** — the crisp, minimal treatment.

The choice is stored in a cookie (`commits_theme`) and read in the root layout, so it's
applied server-side with no flash-of-wrong-theme. Visuals key off `:root[data-style]` in
`app/globals.css` (font swap, underlines, paper, note styling) while a small
`ThemeStyle` context (`components/ThemeStyle.tsx`) swaps theme-aware copy
("make a commit", "you said you'd do this — how did it go?"). The handwritten face is
Caveat, loaded via `next/font`.

## Acceptance criteria → where it lives

- Create account / short onboarding — `app/login`, `app/onboarding`
- Create a commit with a real deadline, persists after refresh — `commit/new`, Supabase
- Cheer / Watch / Join / Comment / Follow — `lib/actions/social.ts`, `lib/actions/commits.ts`
- Creator posts updates — `components/UpdateComposer.tsx`
- Deadlines trigger the unresolved state — `getUnresolvedCommits`, home + owner panel
- "How did it go?" → Ship with proof — `commit/[id]/resolve` → `commit/[id]/ship`
- Not Yet → move deadline (history kept) or close — `commit/[id]/not-yet`
- Shipped posts in feed/profile, watchers notified — `ShippedCard`, ship trigger
- Activity reflects social interactions (grouped) — `app/(app)/activity`
- Open / Done on profiles — `ProfileView`, `me`. Open splits into Big moves
  (one deadline) and Everyday (a repeating cadence); Done holds Shipped and Closed.
- Shareable, unmistakably-Commits share card — `share/[id]` + OG image

## Notes & scoped-out

Per the brief, **not** built: payments, DMs, private groups, AI coaching, streaks/points/
leaderboards, project-management features. Video uploads are architected for (updates/proof
carry `media_url`) but images + links are prioritized in V1.
